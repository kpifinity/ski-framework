# v3.2.0 — Trust, one contract, strict sovereignty

**Released:** 2026-10-30

> **Breaking, by design.** The runtime now starts in strict sovereignty mode
> and refuses to start unless the spec §6 checks pass, and v3.2.0's other
> safety defaults fail closed. Each has an explicit opt-out for demos and
> CI. Existing ledgers, flat-format KGs and pre-v4 ledger entries keep
> working. Read [Upgrading](#upgrading-from-v310) before you deploy.

## Install

```bash
pip install ski-sdk ski-kg-extractor ski-kg-validator ski-audit-ledger ski-model-deploy ski-schemas
docker pull ghcr.io/kpifinity/ski-model:3.2.0
```

## Highlights

### Phase 0: the runtime fails closed where the spec says it must
- **Fail-closed Symbolic Verifier.** It enumerates the obligations itself
  rather than trusting the model's list, so an omitted or masked
  obligation can no longer slip through as CLEAR.
- **KG trust anchors.** A Knowledge Graph loads only if its signature
  verifies against an operator-pinned key (`SKI_KG_TRUST_ANCHORS`), never
  the key the KG embeds.
- **Honest backends.** FakeLLM and first-boot key generation need explicit
  opt-ins, and the model weight hash is verified when pinned.
- **Least-privilege ledger role.** The runtime writes as `ski_ledger_writer`
  (INSERT + SELECT only).

### Phase 1: one contract any implementation can be built against
- **Language-neutral contracts.** An RFC 8785 canonicalizer (spec §7.3),
  JSON Schema, OpenAPI 3.1 and test vectors, with a CI drift check.
- **Ledger v4.** Each entry's hash now also covers the stored envelope, the
  signed transcript and the verifier status, so editing the evidence
  breaks the chain and `audit-ledger verify` reports it. No migration;
  older entries still verify.
- **One Knowledge Graph format.** The runtime loads the spec §3 graph
  (nodes and edges) that `kg-validator`, `kg-extractor` and the docs use,
  signed over the whole graph. The new `ski-model-deploy sign` signs a KG,
  and `scripts/flat-kg-to-graph.py` migrates flat KGs (which still load).
- **Strict sovereignty mode (spec §6).** Five startup checks: a sovereign
  backend, a pinned weight hash, operator trust anchors, a local ledger,
  and no evaluation-path destination outside the deployment. An egress
  guard counts any network call that leaves the deployment during an
  evaluation (`ski_egress_attempts_total`) and stops evaluating in strict
  mode. `GET /api/sovereignty` returns a signed attestation.

### Fixed along the way
- The telemetry buffer now ships in the image and is provisioned by
  compose and Helm. Stateful predicates and the freshness gate work in
  real deployments.
- `audit-ledger replay` re-checks each v3 decision from its signed
  transcript: verdict, verifier status, buffer reading and KG.
- `ski-model-deploy load-kg` works from the command line, and the
  `quickstart.py` walkthrough no longer crashes.

## Conformance

156 conformance tests: 69 Provenance, 30 Durability and 57 Sovereignty.
The new tests cover ledger-v4 tamper detection, live replay, and the
signed graph KG booting in the air gap.

## Upgrading from v3.1.0

1. **Pin the model weights:** set `SKI_MODEL_FILE_SHA256`. Strict mode
   refuses to start without it. Demo and CI stacks set
   `SKI_SOVEREIGNTY=advisory`.
2. **Configure KG trust anchors:** set `SKI_KG_TRUST_ANCHORS` to your
   signing public key(s), and sign KGs with `ski-model-deploy sign`.
3. **Existing database:** apply `reference-implementation/src/ledger/telemetry_buffer.sql`
   once, as the schema owner.

Full steps are in [docs/migrations.md](../migrations.md). For every change,
see [CHANGELOG.md](https://github.com/kpifinity/ski-framework/blob/main/CHANGELOG.md).
